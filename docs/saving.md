# 存档与确定性

## 世界状态

核心存档使用版本化 JSON，当前编码版本为 3。有效配置、地图、时间、实体、资源、建筑、社会、事件与随机流状态共同决定续跑结果；恢复入口处理兼容字段并校验状态摘要。

存档读取通过 `Simulation.CreateForRestore` 与 `SaveLoader`，不把恢复当作重新生成世界。配置、实体世代、存活顺序、目标、库存与系统内部进度需要保留，派生索引按正式恢复路径重建。

## 图形会话

图形客户端额外保存 `client` 元数据：

| 字段 | 内容 |
|---|---|
| `scenario` | 场景选择 |
| `trial` | 试炼、居民队列、危机、额度与稳定进度 |
| `projects` | 工程配方快照、队列、日阶段、政策、管理进度与冻结对照 |
| `blueprint` | 聚落蓝图类型、中心、最后观察日、稳定天数与完成标记 |
| `pin` | 关注人物的稳定编号 |
| `checkpoint` / `experiment` | 非递归实验起点与名称 |

缺失客户端字段使用默认值。未确认的落点不保存；已开工建筑属于核心状态。载入和回溯保留会话进度，镜头和选择重新建立。保存位置由文件对话框决定，个人存档默认忽略提交。

## 可复现的模拟

内核使用明确的随机流和模拟时间；事件、干预、天气与居民行动不能借用系统随机数或系统时钟。相同规则、种子和操作顺序应产生相同状态。

CoreDigest 不包含客户端元数据，所以摘要相同不足以证明工程、试炼和蓝图续跑相同。验证恢复时同时比较核心摘要和会话编码，并继续逐日运行。镜头、检查器、地图图层和视觉动画不能改写内核或消耗其随机流。

Console 可以读取并运行核心状态，但不会继续执行图形会话计划。策略对照使用图形客户端的实验回溯；内核确定性对照使用命令行 digest 模式，见 [构建与运行](build.md)。
