# 版本更新与兼容

项目以源码和 Git 提交标识当前版本。更新记录见 [CHANGELOG](../../CHANGELOG.md)；下载或切换分支时确认使用的是你需要的提交和分支。

## 更新已有项目

先保存游戏并退出。备份个人存档与修改过的 `config/` 参数；查看 `git status --short`，处理需要保留的源码或资源改动。使用主分支更新已有 Git 工作目录时，执行：

```powershell
git status --short
git fetch origin
git switch main
git pull --ff-only origin main
./tools/godot.ps1 -Mode build -Configuration Release
./tools/godot.ps1 -Mode run
```

如果提示没有上游分支或无法快进，先确认分支与本地提交，不使用强制重置覆盖自己的开发成果。通过 ZIP 获取源码时，解压到新目录、配置环境，再载入备份存档；保留旧目录用于对照。

图形运行入口会重建 Debug 程序集并导入资源；只编译 Release 不会刷新编辑器正在使用的 Debug 程序集。若工具链版本变化，按 [安装与启动](getting-started.md) 同步 SDK 与 Godot .NET 编辑器。

## 哪些变化影响已有世界

| 更新内容 | 已有世界的处理 |
|---|---|
| UI、材质、模型和镜头 | 通常不修改核心状态，但仍应检查显示与输入 |
| 模拟默认参数 | 已有存档使用保存的有效规则，不会自动替换成新默认值 |
| 自然住房布局默认值 | 新建图形世界开启；旧存档保留自己的开关 |
| `projects.json` | 历史 SDK 配方；当前图形客户端不加载或推进 |
| 荒野地点 | 新建图形世界生成；旧档缺少 wild 时保留原地图，不重绘 |
| 旧工程、试炼和蓝图 | 元数据被忽略，已存在建筑和地形保留 |
| 核心存档格式 | 必须符合加载器接受的版本；当前写入版本为 4，可读取 v3 并将缺失压实视为零 |
| 客户端会话字段 | 缺失字段使用对应默认值；新增字段要验证实际续跑 |

当前加载器不自动转换其他版本的核心存档。遇到版本不匹配时保留原档，使用匹配的代码版本查看；不要手动改 version 数字冒充格式迁移。具体字段与续跑边界见 [存档与确定性](../development/saving.md)。

## 更新后如何检查

启动一个新世界，检查镜头、菜单和工具；另载入一份旧档副本，检查人物关注、建筑、荒野作用和命名手记状态。恢复时间后观察跨过日界时的进度。修改默认参数或自然地点规则后，分别检查新世界和已保存世界。

开发者还应运行 [开发指南](../development/developer-guide.md) 中对应的检查。发生问题时记录提交、环境、存档版本和操作步骤，见 [故障排查](troubleshooting.md)。

## 文档与资源位置

使用文档位于 `docs/guides/`，开发资料位于 `docs/development/`。当前配图位于 `docs/images/`，旧界面和历史配图位于 `docs/archive/images/`；临时截图使用 `runs/screenshots/`。文档移动不改变游戏存档或资源路径，移动文档与配图时需同步所有引用，维护方法见 [目录与文件管理](../development/repository-layout.md)。

资源目标的可达筛选与紧急进食属于行为规则更新，旧存档格式仍可读取，但后续行动与旧版本轨迹可能不同。连通缓存从当前世界重新推导，不写入存档；读档续跑的确定性应在同一版本内比较。

## 协作分支与实验资料

`main` 保存已合并版本，`codex` 保存当前协作改动。需要跟进协作分支时，将更新命令中的 `main` 换成 `codex`；先确认本地改动，再快进更新，PR 创建不会自动合并代码。

实验结果包含运行器、源码和产物哈希。更新源码后，旧结果保留为对应版本的记录，不当作新提交的实验结果。历史日志与单独请求的整理位置见 [runs](../../runs/README.md)，完整评测目录和 Git 恢复 bundle 保持原结构。
