# 改进器效率与成本回收实验

项目的 RSI 研究对象是**会修改自身改进程序的代理**。程序运行更快、解决任务更多、产出代码更长，都不能单独说明改进过程变强。本工具在原有迁移、冻结、方法撤销与后代分叉的基础上，进一步回答：同样时间能否得到更多收益、后代的增量收益是否值得生成成本、部署多久可能收回投入。

研究范围接近 [STOP 的递归改进程序实验](https://arxiv.org/abs/2310.02304)：修改的是调用模型与优化代码的程序，而非模型权重。这里没有训练模型，也没有认证模型身份。连续任务来源于沙盒的库存、道路与实体生命周期，具体语义见 [连续世界实验](stateful-rsi.md)。

## 时间预算与搜索轨迹

分析先验证完整实验归档，再重放每次调用的实际墙钟时间。在任务预算的 10%、25%、50%、75%、100% 处比较子代理与**拥有相同开发记忆的父代理**，从而减少把新增经验误认为代码改进的混淆。

调用结束后，该次已按开发反馈选择的候选才可使用。不会从留出结果中选择最好的一次。时间 AUC 是在整个代理时间预算中积分的收益：更早得到有效结果比最后一刻才得到相同结果更好。离散尝试 AUC 仍保留在原协议中，两者不混用。

另外记录到首次收益 ≥ 0.15 的受限时间。未达到阈值的任务标记为 censored，按预算终点计算，失败不能删除。这是“达到收益阈值”的时间，不是首次输出正确答案的时间；正确性仍由原协议约束。

这些是原策略轨迹的事后截断，不代表代理获知低预算后会采取的策略。研究预算感知行为应使用不同配置重新运行。五个预算点的区间用于探索，未做多重比较校正；联合筛选只使用预定的完整预算时间 AUC。

## 每秒产生更好后代

对每个分叉、每个未见任务计算：

```text
增量收益率 = (后代搜索能力 − 其起点代理搜索能力)
             / (分摊的后代生成时间 + 后代搜索的已记录成本)
```

父改进器的起点是同记忆父代理，子改进器与方法撤销组的起点是当前子代理。代价包含实际代理调用墙钟，以及代码后端记录的候选、参考 solve 墙钟。失败生成的后代按零能力计分，但保留生成时间；不把接受失败的分叉从样本中移除。

比较“子 − 父”和“子 − 撤销方法”，同时按分叉和任务族进行层次重采样。这样，一个产生更好代码却多花百倍时间的方法，也可能被判为效率下降。区间是小样本探索依据，不是跨平台保证。

**成本账本不完整**：训练、导入编译、输入复制、异常工作进程和完整评估器开销未全部记录。分母是已记录成本的下界，所以该收益率只是这个明确范围内的指标，不能转成费用、token 效率或完整系统吞吐率。报告同时保留原能力与成本，以便检查比率的来源。

## 部署回收与拒绝推断

代码后端直接比较同一任务七组输入上的父、子候选；两者都必须正确、满足内存预算，并且每组 CPU 计时扣除量化余量后以及墙钟均有正节省。任何一组无法确认就输出“无法确认”，不会用一个幸运的中位数外推回收。

通过后，用七组中最小观察墙钟节省量与子搜索、分摊谱系生成成本估算：

```text
乐观回收次数 = ceil(已记录改进投入 / 最小观察节省量)
乐观净节省 = 部署执行次数 × 最小观察节省量 − 已记录投入
```

JSON 给出 1、100、10,000、1,000,000 次执行的敏感性结果。投入遗漏训练和完整评估成本，因此回收次数是**偏乐观的估计**，不是上界；微基准启用 Python 分配追踪，也不能当作无追踪真实部署时间。Kernel 和 HTTP 归档没有这里所需的代码配对记录，会明确输出不可推断，不伪造部署收益。

## 使用

```powershell
# 对已完成的连续世界实验做成本研究
python tools/rsi_efficiency_study.py runs/evaluation/my-rsi --output runs/reports/my-cost-study.json
python tools/rsi_benchmark.py report runs/evaluation/my-rsi --output runs/reports/my-cost-report.html

# 多尝试、短时间预算的非 LLM 控制夹具
python tools/rsi_benchmark.py run benchmarks/rsi-budget-smoke.json --output runs/evaluation/budget-example
python tools/rsi_efficiency_study.py runs/evaluation/budget-example --output runs/reports/budget-example.json
```

输出必须是新文件。JSON 记录原结果和分析器 SHA-256，HTML 展示预算对照、后代收益率、成本与回收原因。分析前重新验证原协议归档；修改过的结果不能获得有效研究输出。原实验不会被写回或改变分数；分析器源码改变后应生成新报告。

成本敏感证据要求同时通过原五项递归证据、完整预算时间 AUC、后代增量收益率和撤销方法收益率。它只是在原证据上增加筛选条件，不能把没有 RSI 证据的实验升级成 RSI。公开夹具即使某个操作性门槛通过，依旧是人为脚本控制，不是模型能力证据。

当前连续世界夹具的两阶段实际归档，在这些新增门槛下仍为零个支持阶段；这说明工具能报告证据不足，不能说明真实模型一定不能改进。接入真实代理时保持 `fixtureOnly: false`，保留失败样本与控制组，并在多个独立种子上重复实验。跨阶段课程不同，不用阶段间斜率声称递归加速。

## 本机控制实验观察

2026-10-08 的 `rsi-budget-smoke.json` 实际执行 992 次代理调用，两个完整阶段、零个失败生成分叉。配置允许每题三次尝试、0.6 秒代理时间，执行次数受实际时间限制，因此不是每题一定用完三次。完整归档在本机 `runs/evaluation/rsi-budget-20261008`，JSON 和 HTML 在 `runs/reports/`；这些输出不随源码提交。

| 对照 | 阶段 1 | 阶段 2 |
|---|---|---|
| 同记忆父子时间 AUC 差异 | 0.165，区间 [0.087, 0.243] | 0.129，区间 [0.003, 0.256] |
| 子改进器减父改进器的增量收益率差异 | −0.168，区间 [−0.922, 0.546] | 0.354，区间 [−0.295, 1.091] |
| 未达到收益阈值的父 / 子任务数 | 12 / 8 | 8 / 6 |
| 成本敏感联合证据 | 未通过 | 未通过 |

这是“更早得到收益，但没有证明每秒产生更好后代”的控制例子。区间与调用速度依赖本机和当次采样，重新运行不应期待相同数字。脚本人为编码了策略变化，没有模型调用；这些数字用于验证研究机制，不能拿来宣传模型 RSI 或跨平台性能。

## 实现入口

`tools/rsi_efficiency_study.py` 负责独立回放分析，`tools/rsi_report.py` 展示研究结果，`tools/test_rsi_efficiency_study.py` 覆盖延迟结果、未完成任务、失败成本、昂贵改进、配对与回收拒绝条件。实验生成和原证据验证仍由 `tools/rsi_benchmark.py` 负责。
