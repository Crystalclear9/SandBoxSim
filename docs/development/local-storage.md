# 本机存储维护

源码、正式文档与游戏资源构成项目本体；安装器、开发工具、导出包、缓存和实验输出各自管理。仓库不会安装系统级 Blender，也不要求改动系统 PATH 或卸载已有的软件。

## 游玩与开发依赖

Windows 独立游戏放在 `artifacts/game/windows/`，保留 EXE 和相邻的数据目录。根目录 `Play-3D.cmd` 优先打开这个包，游玩不依赖 .NET SDK、Godot 编辑器、导出模板或 Blender。源码修改后需要重新导出，见 [构建与运行](build.md)。

继续开发时，使用 [安装指南](../guides/getting-started.md) 恢复 SDK 和 Godot .NET，或指定已有工具链。Blender 仅用于重新转换授权素材，普通构建使用仓库内的衍生网格和贴图，见 [人物素材](human-assets.md) 与 [环境素材](environment-assets.md)。

## 文件分类

| 内容 | 处理方式 |
|---|---|
| 源码、配置、工具脚本、Git 历史 | 保留并随项目维护 |
| 正式文档、配图、网格、贴图和署名 | 保留；不能作为临时截图或下载副本删除 |
| 独立游戏 EXE 和数据目录 | 保留完整可运行包 |
| 私有工具目录 `.sandboxsim-tool/` | 仅移除本项目安装、且已确认没有其他使用者的版本；不卸载系统软件 |
| 下载的安装器、原始 `.blend`、转换试验 PCK | 当前成品已包含必要资源后，可移除本次下载副本；来源、许可和校验清单保留 |
| `bin/`、`obj/`、客户端 `.godot/`、Python `__pycache__/` | 关闭相关构建后可重建的缓存；使用明确路径清理 |
| `runs/screenshots/` | 运行过程中查看的临时截帧；正式配图位于 `docs/images/` |
| 完整实验与研究记录 | 只保留明确需要用于研究或复现的实验；保留时维持完整性，不再使用的开发试验可整体清理 |
| 重复试验压缩包、审计清单和临时 Git bundle | 已不再需要时清理，不默认新增归档 |
| 玩家存档、用户设置、个人备份、系统和共享包缓存 | 保留，不因清理开发环境而删除 |

## 实验归档

需要长期保存的研究实验可选用 `runs/archives/`，不上传源码仓库。归档保留原有相对路径、请求、源码/程序集身份、失败样本与日志；恢复到仓库根目录后可重新检查。日常目录整理不默认保留开发试验、审计清单、旧日志或备份压缩包。

日常清理无需生成新的审计报告或维护归档。删除前确认具体路径与用途，拒绝越界路径、符号链接和 junction；存档保持原内容。源码、正式资源和独立包按各自目录职责保留。

不要使用 `git clean -fdx` 或全盘 PNG/ZIP 通配删除。被 Git 忽略的目录可能包含个人存档、历史实验和恢复备份。原来就存在的 Godot 用户目录、系统 Python/PowerShell、共享 NuGet 缓存和其他应用保持原状。
