# 性能采样与渲染维护

性能运行采用 [评测接口](benchmark.md) 的固定帧预算和独立墙钟。在相同输入下保留模拟摘要、模型细节与交互行为，再比较耗时。本文说明当前机制与采样方法，不把旧版本的本机数字当作当前构建的性能。

## 采样与比较

先编译当前源码，固定机器、供电、后台负载、渲染器、窗口和驱动。纯性能场景不采截图，避免把截图写盘混入渲染对照：

```powershell
./tools/godot.ps1 -Mode build
python tools/evaluate.py run benchmarks/scenarios/render-population.json --output runs/evaluation/baseline-1 --label baseline
python tools/evaluate.py run benchmarks/scenarios/render-population.json --output runs/evaluation/baseline-2 --label baseline
python tools/evaluate.py run benchmarks/scenarios/render-population.json --output runs/evaluation/baseline-3 --label baseline
```

修改实现并重新构建后，以三个新的目录采集候选；配置、限帧、VSync 和环境保持一致。每个样本保留请求、源码/程序集身份、环境与结果。比较单组结果：

```powershell
python tools/evaluate.py verify runs/evaluation/candidate-1
python tools/evaluate.py compare runs/evaluation/baseline-1 runs/evaluation/candidate-1
```

汇总每组至少三次的 FPS、p95 中位数和范围，保留失败样本。平均超过 30 FPS 不等于每帧都在 33.3 ms 内，还需查看 p95/p99/max、超过 33/50 ms 的帧数及实际交互。托管堆快照不是总内存、显存或峰值内存；CPU 区段也不是 GPU 时间。

`visual-landscape.json` 冻结模拟并回放地形远近景，用于外观检查；`visual-architecture.json` 和人物专题场景用于检查模型与交互。它们包含截图或不同相机，不能替代无截图的人口性能场景。扫描材质与更密草丛尚没有当前版本的配对加速证据。

## 交互长帧与时间预算

普通游玩采用 4 ms 主线程追赶预算，每执行一个完整 tick 后检查时间并让出本帧。累计追赶欠账限制为约四分之一秒，单次输入 `delta` 最多取 0.1 秒，避免切回窗口时连续追赶大量 tick。逻辑顺序保持不变；负载过高时实际模拟速度会低于所选倍速。预算无法中断正在执行的重 tick。

地形、自然物和建筑重建分到不同帧。建筑每帧最多创建或替换一个模型，拆除及已有节点的位置、朝向在同步时处理；待执行工作重新读取当前状态，世界切换清空待刷新标记。批量编辑或高速推进时画面可能短暂落后于内核，结果中的 `worldVisuals` 记录三类刷新标记与已缓存建筑数。

固定步长评测按 `ticksPerFrame` 执行全部请求 tick，不使用普通游戏的追赶预算；二者调度口径不同。性能优化不能通过降低世界输入、改变门槛或丢弃模拟步取得通过。

## 地表、水面与植被

地形使用每格 4×4 细分共享顶点，索引与 UV 按地图尺寸缓存。图层和小幅压实变化只更新共享贴图，地形工具或海拔变化才触发网格更新。压实纹理按 8 位精度刷新，核心状态仍连续保存。

扫描颜色纹理启用 mipmap。法线 XY 和粗糙度打包、生成 mipmap 并共享缓存；地表使用 12 个采样器，建筑复用木、石、灰泥资源。纹理缓存节省重复加载，但增加常驻内存，不等于帧率已经改善。

近景草丛采用共享的 403 三角面扫描衍生网格，每个符合筛选条件的格子放置三个错位实例，按 24 米区域使用 MultiMesh 绘制。距离相机 24–32 米逐渐缩退，34 米后整批裁剪，关闭草叶投影，包围盒保留风摆余量。存在条件读取植被、火烧、地形与建筑占用；压实伏低通过共享贴图更新。

阔叶树和针叶树保留完整导出叶片索引，避免自动减面破坏树冠。多材质、叶片和阴影仍有较高绘制成本，不能用草丛的距离裁剪推断树木成本同样降低。环境预算与来源见 [环境素材](environment-assets.md)。

水面岸线使用 16 邻域纹理采样的连续双三次插值，河床采用同一岸线函数；实际河床高度存入 Rfloat 纹理用于深浅水色。该着色成本需要在相同相机和水面覆盖率下比较，水色更换不构成加速证据。

地图阴影采用两级级联，距离随镜头在 16–160 米内调整；近景法线偏移为 0.2，镜头距离从 16 到 40 米时逐渐过渡到原有 1.0。图册使用独立正交阴影，范围为 `max(4, 卡片尺寸×3)`，深度/法线偏移为 0.05/0.2；平面地台接收模型阴影，但不投射自身阴影，减少近景条带与漏光斑块。

结果的 `renderQuality` 保存地图阴影距离、偏移和 MSAA；有图册时，`galleries` 记录每张卡片实际灯光的模式、范围、偏移及地台投影设置。条件不同的样本不能直接比较，缺少新增条件的旧结果应重新建立基线。这是质量设置变化，不是帧率优化结论。

## 建筑与模型缓存

[WorldView3D.Buildings.cs](../../src/SandBoxSim.Godot/WorldView3D.Buildings.cs) 按槽位、生成号、身份、种类及完工状态维护建筑节点。道路变化更新朝向，地形变化更新位置和贴地石基；四角深度不变时复用基座网格。拆除立即移除节点，换世界或读档清空缓存。

住房保留 140 个稳定身份组合。近远景按 24/32 米滞回切换；静态网格命中缓存后直接创建独立节点，避免重建随后丢弃的门、瓦片和木作。CPU 合并由 [NatureModels.MeshBatching.cs](../../src/SandBoxSim.Godot/NatureModels.MeshBatching.cs) 按材质批量变换顶点、法线、UV、索引及顶点色，不跨越独立运动关节，不替代手部或肩部蒙皮。

住房生活附件只在近景显示，状态未变时复用。地面物资每次同步最多补建四个模型，累计创建达到 2 ms 后不再开始下一个，超过 55 米隐藏；单次创建不可中断，预算属于软限制。作物按种类与阶段共享近远景网格，远景减少细节。

衣装配件复用网格缓存；衣身表面采样缓存实际顶点和索引，并先排除高度不相交的三角面。人物按可见性与距离安排姿态更新，保持位置插值，按实际累计帧时间消费动作；近远景切换不重置真实动作进度。隐藏的肖像、手记和曲线减少刷新。

近景上衣加载缝片生成的三种蒙皮，每种 6,784–6,840 三角面；网格和成品哈希校验按剪裁缓存，创建带配色的实例时复用同一几何。袖子骨骼数组只读取一次，不能在逐顶点循环中反复从 Godot 导出。近景移除原分件上袖，远景恢复轻量分件与原有动作。连续茅草坡面按近远景采样不同密度。它们属于模型质量改动，没有当前版本的配对帧率结论。

近景动物短毛束按种类缓存：狼增加 13,200 三角面，鹿增加 7,200 三角面，各增加一个绘制表面；共用原有骨骼更新。毛束层在 18 米外隐藏，范围余量 3 米。该改动增加近景成本，尚无配对帧率结论。

近景手掌与前臂连体蒙皮按左右及肤色缓存，每侧 18,205 三角面，替换旧手部、前臂与肘球；共用现有 16 骨手部骨架。远景保留 1,400 三角面手部和 3,687 三角面静态前臂，腕端保留埋入重叠，近远切换不重复绘制。鞋带网格按鞋楦缓存，各 768 三角面，合并到原有脚部材质组。模型变化没有配对帧率结论。

## CPU 区段

`result.json` 的 `cpuScopes` 在预热结束时清空，通过 [RenderProfile.cs](../../src/SandBoxSim.Godot/RenderProfile.cs) 记录主线程工作：

| 区段 | 工作范围 |
|---|---|
| `SimulationTicks` | 内核 tick 与自然地点推进 |
| `CheckTerrain` | 变化签名检查及触发的同步 |
| `BuildTerrain` | 地形、水面网格与纹理数据 |
| `BuildNature` | 自然物、地点和空间批次 |
| `BuildBuildings` | 建筑差异、朝向与聚落标签 |
| `CreateBuilding` | 新建或变更建筑的网格、节点 |
| `AnimateActors` | 角色位置、朝向、携带物与姿态 |
| `SyncEntities` | 角色增删、职业/年龄变化和危险表现 |

每项含 `calls`、`totalMs`、`maxMs`。父区段包含子区段，不能相加作为总 CPU 时间；墙钟还包含引擎渲染、UI 和调度。新增区段时基线与候选须采用同一计时范围，观察不能修改模拟状态。

## 检查与输出管理

```powershell
./tools/godot.ps1 -Mode test
python -m unittest discover -s tools -p test_evaluate.py
python tools/fetch-surface-materials.py --verify
```

自检覆盖节点复用、朝向/高度改变、贴地基座、完工、拆除、槽位复用、几何预算及握持。实际窗口另查近远景、材质、鼠标与暂停；无头自检或识别分数不衡量美感。

完整实验放在 `runs/evaluation/<独立名称>/`，请求、结果、图片、答案与溯源整体保留。明确不再使用的开发试验可整体清理；文档不保证旧本机实验仍存在，不保留无来源的旧 FPS 作为当前基线。正式配图、素材与存档分别管理，见 [目录职责](repository-layout.md)。

游戏渲染、HTTP 程序成本和代理搜索效率具有不同计时范围。程序效率使用 [在线效率](online-efficiency.md)，代理研究使用 [代理改进协议](rsi-improver.md)，不能把单次加速比解释为 RSI。
