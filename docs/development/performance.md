# 性能采样与渲染维护

性能运行采用 [评测接口](benchmark.md) 的固定帧预算和独立墙钟。在相同输入下保留模拟摘要、模型细节与交互行为，再比较耗时。本文说明当前机制与采样方法，不把旧版本的本机数字当作当前构建的性能。

近景睫毛随人物头脸细节切换隐藏；耳内短毛在 18 米外隐藏，狼角膜在 20 米外隐藏。果实细节并入共享灌丛后统一生成屏幕 LOD，灌丛在 42 米外隐藏，避免远景持续绘制小果粒。窗台并入已有建筑静态缓存。新增着色和局部网格会改变绘制负载，比较效率时需重新采同场景基线；这些预算不是当前帧率承诺。

花甸共享三种配色、两个阶段的花株网格，以 24 米分块批次绘制，42 米外隐藏，不为每朵花创建独立绘制节点。CPU 保存各批次的变换，土地压实显示刷新时只上传高度发生变化的实例，避免 GPU 变换读回；包围盒增加 4 厘米余量覆盖细微沉降。无窗口自检检查 CPU 位置，图形自检同时检查实际实例变换。

## 采样与比较

先编译当前源码，固定机器、供电、后台负载、渲染器、窗口和驱动。纯性能场景不采截图，避免把截图写盘混入渲染对照：

```powershell
./tools/godot.ps1 -Mode build
python tools/evaluate.py run benchmarks/scenarios/render-population.json --output runs/evaluation/baseline-1 --label baseline
python tools/evaluate.py run benchmarks/scenarios/render-population.json --output runs/evaluation/baseline-2 --label baseline
python tools/evaluate.py run benchmarks/scenarios/render-population.json --output runs/evaluation/baseline-3 --label baseline
```

修改实现并重新构建后，以三个新的目录采集候选；配置、限帧、VSync 和环境保持一致。每个样本保留请求、源码/程序集身份、环境与结果。比较单组结果：

```powershell
python tools/evaluate.py verify runs/evaluation/candidate-1
python tools/evaluate.py compare runs/evaluation/baseline-1 runs/evaluation/candidate-1
```

汇总每组至少三次的 FPS、p95 中位数和范围，保留失败样本。平均超过 30 FPS 不等于每帧都在 33.3 ms 内，还需查看 p95/p99/max、超过 33/50 ms 的帧数及实际交互。托管堆快照不是总内存、显存或峰值内存；CPU 区段也不是 GPU 时间。

`visual-landscape.json` 冻结模拟并回放地形远近景，用于外观检查；`visual-architecture.json` 和人物专题场景用于检查模型与交互。它们包含截图或不同相机，不能替代无截图的人口性能场景。扫描材质与更密草丛尚没有当前版本的配对加速证据。

## 交互长帧与时间预算

普通游玩采用 4 ms 主线程追赶预算，每执行一个完整 tick 后检查时间并让出本帧。累计追赶欠账限制为约四分之一秒，单次输入 `delta` 最多取 0.1 秒，避免切回窗口时连续追赶大量 tick。逻辑顺序保持不变；负载过高时实际模拟速度会低于所选倍速。预算无法中断正在执行的重 tick。

地形、自然物和建筑重建分到不同帧。建筑每帧最多创建或替换一个模型，拆除及已有节点的位置、朝向在同步时处理；待执行工作重新读取当前状态，世界切换清空待刷新标记。批量编辑或高速推进时画面可能短暂落后于内核，结果中的 `worldVisuals` 记录三类刷新标记与已缓存建筑数。

固定步长评测按 `ticksPerFrame` 执行全部请求 tick，不使用普通游戏的追赶预算；二者调度口径不同。性能优化不能通过降低世界输入、改变门槛或丢弃模拟步取得通过。

## 几何与表面预算

木石米制构件按实际尺寸与倒角半径缓存，维持每帧建筑补建额度和静态合并。动物触须各物种复用网格，只在 14 米内绘制、关闭投影，新增表面意味着近景负载发生变化；草花仍受 1,400 三角面、空间批次和 42 米裁剪限制。植物风摆的表面方向修正及鼻镜微纹在着色器内计算，不增加逐帧 CPU 网格重建。上述变化没有配对加速结论，性能比较须使用当前相同渲染版本。

## 地表、水面与植被

地形使用每格 4×4 细分共享顶点，索引与 UV 按地图尺寸缓存。图层和小幅压实变化只更新共享贴图，地形工具或海拔变化才触发网格更新。压实纹理按 8 位精度刷新，核心状态仍连续保存。

扫描颜色纹理启用 mipmap。法线 XY 和粗糙度打包、生成 mipmap 并共享缓存；地表使用 12 个采样器，建筑复用木、石、灰泥资源。纹理缓存节省重复加载，但增加常驻内存，不等于帧率已经改善。

近景草丛采用共享的 336 三角面折面弯叶，每个适宜格子最多两个稳定候选，按植被量、坡度和外围根接地筛选，按 24 米区域使用 MultiMesh 绘制。距离相机 24–32 米逐渐缩退，34 米后整批裁剪，关闭草叶投影，包围盒保留风摆余量。存在条件读取植被、火烧、地形与建筑占用；压实伏低通过共享贴图更新。

阔叶树和针叶树保留完整导出叶片索引，避免自动减面破坏树冠。多材质、叶片和阴影仍有较高绘制成本，不能用草丛的距离裁剪推断树木成本同样降低。环境预算与来源见 [环境素材](environment-assets.md)。

水面读取实际地形高度纹理的四个角点、同一三角剖分和压实修正，按深度裁切；实际河床高度存入 Rfloat 纹理用于深浅水色。该着色成本需要在相同相机和水面覆盖率下比较，水色更换不构成加速证据。

地图阴影采用四级级联、深度偏移 2.4，距离随镜头在 16–160 米内调整；近景法线偏移为 0.2，镜头距离从 16 到 40 米时逐渐过渡到原有 1.0。设置用于减少坡面自遮挡条纹，地形与模型仍投射阴影；更多级联也有渲染成本，不能视为性能提升。图册使用独立正交阴影，范围为 `max(4, 卡片尺寸×3)`，深度/法线偏移为 0.05/0.2；平面地台接收模型阴影，但不投射自身阴影，减少近景条带与漏光斑块。

结果的 `renderQuality` 保存地图阴影距离、偏移和 MSAA；有图册时，`galleries` 记录每张卡片实际灯光的模式、范围、偏移及地台投影设置。可见人物肖像另有 `portrait`，读取实际子视口分辨率、MSAA、背景、环境光与三盏灯的条件。人物手记的显示入口为 108×138 缩略肖像，展开后使用同一视口；面部、双手和缩略图关闭主光阴影，全身模式启用接地阴影，柔光和侧光改变现有灯光而不增加灯数。条件不同的样本不能直接比较，缺少实际光线、视口与布局条件的旧结果应重新建立基线。皮肤和布料细节仍有着色成本，质量设置变化不是帧率优化结论。

## 建筑与模型缓存

人物观察窗复用档案中的 `ResidentPortrait` 和 3D 世界，只在界面容器间移动；关闭后返回原容器，不创建第二份角色或重复骨架。观察窗最大为 1320×860，附带实时状态栏；展开后的视口更大，像素填充和 MSAA 成本也更高，`renderQuality.portrait.resolution` 记录实际尺寸；展开样本与紧凑档案不能当作同条件性能比较。`ui-portrait-window` 用于交互回归与实际模型观察。

[WorldView3D.Buildings.cs](../../src/SandBoxSim.Godot/WorldView3D.Buildings.cs) 按槽位、生成号、身份、种类及完工状态维护建筑节点。道路变化更新朝向，地形变化更新位置和贴地石基；四角深度不变时复用基座网格。拆除立即移除节点，换世界或读档清空缓存。

住房保留 140 个稳定身份组合。近远景按 24/32 米滞回切换；静态网格命中缓存后直接创建独立节点，避免重建随后丢弃的门、瓦片和木作。CPU 合并由 [NatureModels.MeshBatching.cs](../../src/SandBoxSim.Godot/NatureModels.MeshBatching.cs) 按材质批量变换顶点、法线、UV、索引及顶点色，不跨越独立运动关节，不替代手部或肩部蒙皮。

住房生活附件只在近景显示，状态未变时复用。地面物资每次同步最多补建四个模型，累计创建达到 2 ms 后不再开始下一个，超过 55 米隐藏；单次创建不可中断，预算属于软限制。作物按种类与阶段共享近远景网格，远景减少细节。

居民名录按需显示，每页最多 64 个结果控件，搜索覆盖全部存活居民；人口与角色资料低频刷新，输入筛选即时生效。分页与筛选只改变界面，不创建模拟居民。

衣装配件复用网格缓存；衣身表面采样缓存实际顶点和索引，并先排除高度不相交的三角面。人物按可见性与距离安排姿态更新，保持位置插值，按实际累计帧时间消费动作；近远景切换不重置真实动作进度。隐藏的肖像、手记和曲线减少刷新。

足部与狼尾权重在资源创建时缓存，逐帧只更新关节姿态，爪蹄网格按物种和足部缓存，不逐帧扫描三角面。地面法线增加每足四次邻域高度采样；该模型质量改动没有新的成对帧率结论。

近景上衣加载缝片生成的三种蒙皮，每种 7,648–7,752 三角面；袖根采用连续垂坠与宽折谷，源米制 UV2 用于随蒙皮的细缝线；袖窿、侧胸和配件共用绑定坐标的局部肩权重，来源衣片保留三骨肩袖权重，当前成人运行衣装增加一根骨盆衣料骨以形成四骨腰背过渡，不逐帧重建网格；网格和成品哈希校验按剪裁缓存，创建带配色的实例时复用同一几何。袖子骨骼数组只读取一次，不能在逐顶点循环中反复从 Godot 导出。近景移除原分件上袖，远景恢复轻量分件与原有动作。连续茅草坡面按近远景采样不同密度。它们属于模型质量改动，没有当前版本的配对帧率结论。

当前成人裤装为五骨（腰部、左右大腿与左右膝部），几何面数保持不变，裤脚随膝部接回靴口；上衣近景四骨，远景仍为简化静态衣料。上述形体与绑定改变需要按 `bodyFrame=lumbar-drape-v8` 重采配对性能基线，不能据原版本数据声称帧率提升。

正式近景鹿、狼包含护毛、眼睑和足部细节后的完整面数分别为 23,988／23,956，共享几何与材质缓存；运行绑定为鹿 18／狼 21 关节。护毛在 18 米外隐藏，新增爪蹄细节在 14 米外隐藏。足尖轮廓在读取资源时调整，狼不增加面数，鹿后蹄增加 20 面；远景索引 LOD 共用调整后的顶点，不新增绘制表面。模型质量变化没有配对帧率结论。

近景手掌与前臂连体蒙皮按左右及肤色缓存，每侧 18,205 三角面，替换旧手部、前臂与肘球；共用现有 16 骨手部骨架。远景保留 1,400 三角面手部和 3,687 三角面静态前臂，腕端保留埋入重叠，近远切换不重复绘制。鞋带网格按鞋楦缓存，各 768 三角面，合并到原有脚部材质组。模型变化没有配对帧率结论。

## CPU 区段

`result.json` 的 `cpuScopes` 在预热结束时清空，通过 [RenderProfile.cs](../../src/SandBoxSim.Godot/RenderProfile.cs) 记录主线程工作：

| 区段 | 工作范围 |
|---|---|
| `SimulationTicks` | 内核 tick 与自然地点推进 |
| `CheckTerrain` | 变化签名检查及触发的同步 |
| `BuildTerrain` | 地形、水面网格与纹理数据 |
| `BuildNature` | 自然物、地点和空间批次 |
| `BuildBuildings` | 建筑差异、朝向与聚落标签 |
| `CreateBuilding` | 新建或变更建筑的网格、节点 |
| `AnimateActors` | 角色位置、朝向、携带物与姿态 |
| `SyncEntities` | 角色增删、职业/年龄变化和危险表现 |

每项含 `calls`、`totalMs`、`maxMs`。父区段包含子区段，不能相加作为总 CPU 时间；墙钟还包含引擎渲染、UI 和调度。新增区段时基线与候选须采用同一计时范围，观察不能修改模拟状态。

## 检查与输出管理

```powershell
./tools/godot.ps1 -Mode test
python -m unittest discover -s tools -p test_evaluate.py
python tools/fetch-surface-materials.py --verify
```

自检覆盖节点复用、朝向/高度改变、贴地基座、完工、拆除、槽位复用、几何预算及握持。实际窗口另查近远景、材质、鼠标与暂停；无头自检或识别分数不衡量美感。

完整实验放在 `runs/evaluation/<独立名称>/`，请求、结果、图片、答案与溯源整体保留。明确不再使用的开发试验可整体清理；文档不保证旧本机实验仍存在，不保留无来源的旧 FPS 作为当前基线。正式配图、素材与存档分别管理，见 [目录职责](repository-layout.md)。

游戏渲染、HTTP 程序成本和代理搜索效率具有不同计时范围。程序效率使用 [在线效率](online-efficiency.md)，代理研究使用 [代理改进协议](rsi-improver.md)，不能把单次加速比解释为 RSI。

模型图册的隐藏背景不创建天空辐照或阴影资源；各展示台仍使用自己的世界、灯光和相机。客户端自检检查背景隔离，原生测试还应检查进程退出日志中的资源诊断。

## 头部细分与运行缓存

动物头骨细分仅在源网格首次读取时执行，最多处理 400 组物理边，之后各实例共用结果并使用屏幕 LOD。不会逐帧细分，也没有降低动物数量或改变模拟步进。其近景图元数量已变化，需要按当前渲染版本重新建立基线。

开发启动器将支持的平台用户缓存放到 `.tools/godot-state/`，避免目录不可写而丢失着色器缓存。缓存位置策略进入评测执行元数据；冷启动与已有缓存的预热成本应分别记录，不能据此直接宣称模拟程序加速。

近景护毛另增加鹿 2,400 面／狼 3,840 面及每只一个共享网格实例，18 米外不绘制；不在 CPU 每帧计算毛发。整只动物的表面、眼部、耳毛、触须与护毛合计接受 24,000 面上限检查。人物湿润眼缘增加 768 面、共用源头部 LOD，并由现有眨眼时间更新。新版本应重新测量相同视角的帧耗时，不能将视觉变化直接称为性能提升。

沉浸模式仅隐藏控件，地图仍为原来的全窗口尺寸；`renderQuality.interfaceVisible` 记录其状态。它不减少动物、暂停模拟或改变测量分辨率，普通 UI 场景和隐藏 UI 场景需分别记录。

## 观察窗口与眼部细化

人物观察窗的对数距离滑条与原镜头共享状态，不新增子视口；主动环视只更新当前人物的观察角度，关闭／失焦／手动接管／关闭动效时停止。领口包边为每种剪裁缓存的 1,164 面，共用原材质并合入身体网格，替换原 2,304 面独立领圈；这属于局部预算变化，不代表整机帧率收益。人物主补光参数已改变，视觉与耗时对照应建立新基线。

人物资料的概览、生活和决策共享同一人物及视口，页面切换不重新创建模型；观察窗的柔光／侧光复用原三盏灯。角膜起伏在共享眼球网格生成时计算，不增加眼球顶点或逐帧 CPU 几何工作；材质的第二反光层增加片元着色成本，衣料也调整了法线与反光，不能据此声称帧率提升。性能比较须使用同一灯光预设、渲染版本和观察页面。

手记中的 108×138 缩略肖像和展开观察窗继续复用同一模型视口；缩略状态隐藏工作室工具栏，不再与大图重复创建渲染场景。`NatureModels.HandSurface.cs` 继续使用近景原皮肤／甲面两表面与骨骼，绑定坐标和掌背掩码在网格创建时写入，远景跳过细纹计算；腕部截面在首次网格创建时统一拟合、修正法线，不增加三角面或逐帧几何重建；近景的程序掌纹与甲面仍增加片元工作，不能称为免费细节或整体提速。

## 草甸、屋瓦与眼部动作

草甸每丛由 403 面扫描草改为 336 面折面叶片，分布也已改变，仍采用 24 米分块、34 米裁剪。分布缓存使用候选位掩码，仅跨过候选阈值才重建；踩踏时只更新变动地块邻域的实际根变换。不因此直接宣称整体 FPS 提升。屋瓦单模板从 252 降为 96 面，增加铺设排数和半瓦后仍减少瓦坡总面数；六种色差写入共享顶点色，不增加每瓦材质。实际帧耗时仍需同机、同分辨率、相同视角的新基线。

鹿／狼闭眼盖片分别增加 352／560 面；计入鹿后蹄补点后，整只近景表现共 23,988／23,956 面，保持原 24,000 面上限。睁眼时覆盖网格隐藏，闭眼时只更新现有个体材质参数；构建几何和来源 UV 投影仅在共享缓存创建时执行；投影先按眼区包围盒预筛源三角并缓存重心，再执行原有距离与最近面判定，自检与完整扫描对照实际 UV，不把局部算法复杂度下降当作整机帧率成绩。人物视线只更新眼球节点的旋转，不在每帧重新生成网格。

水面不再每像素对逻辑水格做 16 点三次插值；改为读取实际地形三角面及四个角点的压实值，确保岸线一致。这是显示修正，不能把不同水面像素覆盖范围的耗时差异直接当作模拟内核加速。

`WorldView3D.Shoreline.cs` 在 `BuildTerrain` 重建时预计算 5×5 邻域水陆覆盖，复用 16 种细网格相位的紧支撑权重，并对实际足区、合法通路和水格中心约束；`HeightAt` 的临水距离查询复用核心缓存。沿用原地形网格和高度纹理，不增加顶点、材质或着色器采样器；较宽邻域增加覆盖计算工作，实际成本需查看同场景 profile，不新增逐帧全地形重建。地表 tint 从 RGB 改 RGBA，以既有 alpha 携带植被量并复用原片元采样，16 档外观签名约有 6% 量化间隔；没有新增采样器、场景节点或 draw call。草甸只改变原两个候选的宽矮／窄高比例，分块、单簇面数与距离预算不变，仍应重建视觉和耗时基线。

`WorldView3D.ActorGrounding.cs` 对安全相邻移动保留指数插值。未知跨步同步逻辑中心；仅近岸追加实际脚区支撑查询，使用缓存读取委托，不维护无限轨迹队列或逐帧扫描全图。该保护增加局部高度查询，高倍速可观察到位置同步，不能称为平滑回放全部逻辑路径或帧率提升。

## 发根与穗轴

野果灌丛在 `NatureModels.Bramble.cs` 中按结果状态缓存，结果／无果实际为 31,616／16,608 三角形，分别受 32,000／17,000 面约束，沿用 42 米显示距离和共享屏幕 LOD。叶柄、主枝与果梗并入同一植物材质表面，果实保留单独材质；单果 21 果粒合计 1,008 面。形态和预算同时改变，不能把不同画面直接当作 FPS 对照。

最近工具入口预建四个按钮与一个紧凑菜单，只在选择或打开时更新，不逐帧重建。人物环视每帧只推进观察角度；距离文字、滑条和预设状态由实际操作更新，环视时不反复刷新不变的读数。

发根闭环、连通域与距离在每个模型构造器的来源族缓存中计算，逐帧不运行图搜索；原发片面数、表面数和贴图不增加。根带着色仍有片元成本，原始纹理 Alpha 和 Scissor 保留。芦苇单丛由 5,824 降为 5,068 三角形，同时增加实际连接的穗轴；形体已变，不能把不同画面负载当作配对帧率收益。

观察窗最大区域扩大到 1320×860，MSAA 子视口会增加像素负载；分组工具栏、固定物资操作区与滚动正文改变界面布局。比较耗时应固定新构图、窗口和渲染版本。

## 字体缓存

Noto Sans SC 与符号字库约 19 MB 原始数据，正文、标题和数字变体共享来源，按实际使用的字号与字形建立缓存；不在每帧读取或散列字体。哈希和字形检查在自检时执行。字体与系统回退策略属于视觉基线的一部分，不能将不同字库或不同排版的帧耗时直接当作优化收益。
