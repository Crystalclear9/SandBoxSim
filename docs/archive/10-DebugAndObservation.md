## 交互观察

运行 `pwsh -File ./tools/run.ps1 -Agents 30`。方向键/WASD 平移，+/− 缩放，
Space 暂停，0/1/2/4/8 调整速度，O 切换叠加层，H/F1 查看帮助，Enter 检查视野中心。
渲染在 Console 项目，模拟状态在 Core；观察不消耗模拟随机数。

## 用报告解释变化

```powershell
pwsh -File ./tools/run.ps1 -Mode snapshot -Seed 839102 -Days 100 -Agents 40 -SnapshotDays 25 -OutDir runs/experiment
pwsh -File ./tools/test.ps1 -Filter EconomyDiagnostics
pwsh -File ./tools/test.ps1 -Filter BuildingDiagnostics
```

报告、每日统计、事件与 PNG 快照写入指定输出目录。先看人口和资源曲线，再用事件查死因、迁移和建造。
当前已实现出生与农业。人口归零时应检查死因、食物、床位和水源，不能只看世界资源总量。

| 症状 | 检查入口 | 可能原因 |
|---|---|---|
| 持续饥饿却不采食物 | Utility 分数、动作选择统计 | 工作效用压过生存效用 |
| 有木材却不建房 | 材料门槛、选址规则、建筑诊断 | 材料不可达或选址失败 |
| 来回存取物资 | 地面库存与携带阈值 | 存放/取回阈值间隔太小 |
| 相同实验结果不同 | digest 模式 | RNG 消耗顺序、配置或调度顺序变化 |
| NaN/负库存 | `Simulation.ValidateInvariants` | 状态写入错误；现有校验主要覆盖 Tile |

## 确定性验证

`pwsh -File ./tools/run.ps1 -Mode digest -Seed 4242 -Ticks 43200 -Agents 30`
会运行两次相同 seed 并比较摘要，再检查不同 seed 的结果。

### 存档与读档（M4b）

```powershell
# 跑 20 天并留一份存档
.\tools\run.ps1 -Seed 555 -Days 20 -Agents 30 -SaveFile runs\lab\w.simsave

# 从存档继续（世界状态完全来自存档）
.\tools\run.ps1 -LoadFile runs\lab\w.simsave -Days 20
```

**存档自带状态摘要与分段摘要**，因此读档可以自己判断"是否恢复出了同一个世界"，
并把不一致定位到具体段落：

```
写档时：7d6ad81f39d8f531
读档后：145adea767c14743
首个不同的段落：stats=e005eeeb9841da47（读档后为 e005dceb9841bbb1）
```

这一点是**刻意设计**的：读档的正确判据是"摘要与写档时一致"，
而如果这个期望值只存在于写档进程的内存里，任何一次读档失败都只能靠
"再跑一遍对照"来发现 —— 实现过程中正是这样被坑了很久
（存档进程打印一个摘要、读档进程打印另一个，但没有任何一处把两者对上）。

分段摘要也是定位"读档漏了状态"的主要工具：它把"一个大数字对不上"
翻译成"是动物那一段对不上"，再配合逐字段对比就能直接找到漏掉的字段。
M4b 期间靠它定位了 **五个**"不进摘要但影响未来行为"的字段
（小数步进度、寻路下一步缓存、迁移冷却、动物存活列表顺序、chunk 聚合统计）。

> **读档失败会明确报错并中止**（退出码 1），不会静默退回一个新世界 ——
> 静默退回是最坏的一种失败方式：玩家以为自己在继续玩原来的世界。

## 观察个体：检查器与效用分解

`Enter` 选中视野附近最近的人，右侧面板会显示：

* **他是谁**：名字、年龄、生命阶段、当前动作与进度、目标与位置；
* **他过得怎么样**：健康 + 四条需求条（颜色随危险程度变化）、随身物资、六维性格；
* **他为什么这么做**：**效用分解表** —— Top-N 候选动作的效用，
  以及被选中动作的**逐条考虑项**（输入值 → 曲线输出 → 权重 → 加权贡献）。

第三段是关键：**可解释性不是这份 UI 做出来的，而是 M1 的数据结构留下的**
（`UtilityBreakdown` / `ActionScore` / `Consideration`），此前只是没有出口。
有了它，"这个人为什么在砍树而不是去喝水"是一个**可以直接读出来的答案**，
而不是需要靠猜测或加日志。

按 `F` 让相机跟随他 —— 长跑观察一个人一辈子时，手动跟着走是不现实的。

## 观察世界：叠加层与实体

`O` 循环切换叠加层。除了地形/肥沃/湿度/温度/木材/食物/植被/火险/可通行之外，
M4a 起还有三层与**实体**相关的：

| 叠加层 | 回答的问题 |
|---|---|
| **人口** | 人聚在哪里、哪里被住空了 |
| **AI 状态** | 这片区域的人主要在**干活**、在**赶路**、还是在**睡觉** |
| **建筑** | 房子盖在哪、哪个仓库快满了（仓库按装满程度从蓝到红） |

人的颜色编码**当前状态**，且**生存告急优先于一切**（极度饥饿/干渴的人恒为告急色）——
那是玩家最需要立刻看到的信息。

覆盖优先级是 **建筑 < 动物 < 人**：人盖住建筑，因为玩家在地图上主要追踪"人在做什么"。

PNG 快照同样画实体，并与 TUI **共用同一份配色实现**（`OverlayPalette`），
因此"报告里的图"和"屏幕上的图"不可能讲两个故事。

## 玩家工具：把"观察"变成"实验"

`TAB` 打开上帝工具面板（4 类 19 个工具，只能改**条件**）。
每个工具执行后底栏会回显"做了什么" —— 因为恩惠类工具（地力 / 再生 / 天气）
点下去只看到数值变化，没有回显会让人以为工具坏了。

**做实验的推荐流程**：

1. 存一份基线（`--save-file`）；
2. 从基线读档，施加**一个**干预；
3. 跑同样多的 tick，与基线比较摘要 / 统计 / 快照；
4. 因为读档让我们从**完全相同**的起点出发，
   所以观察到的差异可以干净地归因到那一个干预上。

这是"玩家创造条件，而不是创造结果"这句话在**操作层面**的落地。
