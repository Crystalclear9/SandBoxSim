# 生态工坊：经营与扩展
工程图册为土地建立初始条件，土地管理决定它在之后如何变化。它们都作用于真实地块，没有自动建城或强制移民。

## 一种值得尝试的组合
在缺粮居民附近找到可达空地，先安排湿地修复，再在相邻或重叠的适用土地上安排食物绿洲。完成后把湿地设为“维护”，粮地先设为“维护”，观察湿度、食物与居民行动。

接着将粮地切换到“采集”。资源优先会补充地表资源，同时每个适用地块消耗 0.05 湿度、0.025 肥力和 0.03 植被，直到条件不足。湿地可以帮助缓解水分压力，但不能保证所有生态条件一直满足。切回“自然”，额外管理停止，模拟中的天气、再生和采集继续运行。

先观察居民是否真的能够到达土地，再比较当前地表存量和人口需求。报告不统计背包与仓库，图上的粮食也不是居民已经吃到的粮食。

## 六种初始条件
| 工程 | 建立条件 | 长期经营 |
|---|---|---|
| 食物绿洲 | 改善草地肥力、补充食物、局部降雨 | 维护补充少量食物；资源优先增加投入并消耗土地条件 |
| 防火走廊 | 逐段清理横向三格宽走廊，形成道路 | 保持走廊无燃料；两种管理模式均维持隔离 |
| 湿地修复 | 连续增加湿度与肥力 | 维护涵养土壤；资源优先在适用粮地补充食物 |
| 林地复苏 | 分圈恢复适用土地上的森林 | 维护补充木材并修复植被；资源优先补充更多木材，消耗土地条件 |
| 迁徙通道 | 逐段建立斜向三格宽小径 | 持续保持通道；两种管理模式均维持道路 |
| 林粮镶嵌 | 在适用土地上建立分区林地与粮地，再降雨 | 维护补充混合资源；资源优先只作用于适用粮地 |

“资源优先”是玩家投入型干预：它补充可被居民采集的地表节点，不会把物资直接送进背包或仓库。容量已满时不会突破上限，土壤代价仍会发生。它不是新增 NPC 职业或自动采集建筑。

水域、山地、熔岩和既有建筑始终受到保护。额外限制由配方决定，例如避开道路、森林或正在燃烧的土地。

## 范围、时间与管理
落点预览允许选择半径 3、5、8。默认费用是 24 + 半径 × 2，分别为 30、34、40 点。默认配方均分三个游戏日界建立；可配置配方支持 1–8 个阶段。

最多同时建设四项、持续管理四片土地，保留最近十二条记录。淘汰历史时不会删除正在建设或管理的土地。停止建设只停止未来阶段，不退款、不撤销已生效部分；完成后选择“自然”停止额外管理。

自由探索不扣干预预算，维护仍受地形、水土、资源容量和植被条件约束。条件不足时暂停当日作用，下一日重新检查。

当前数据是实时观察，完工对照保留为冻结报告。展开“完工对照”查看建设前与完工时的差异；之后管理不会改写它。

## 增加自己的工程配方
客户端文件为 [projects.json](../../src/SandBoxSim.Godot/assets/gameplay/projects.json)。编辑它，再创建新世界。现有存档嵌入原配方，以免修改配置后让旧世界的后续结果突然变化。

在 projects 数组末尾增加一个对象，例如：

    {
      "key": "water_meadow",
      "name": "蓄水草甸",
      "brief": "先涵养土壤，再建立草甸；维护继续补充土壤水分。",
      "art": 2,
      "excludeForest": true,
      "excludeRoad": true,
      "noBurning": true,
      "baseCost": 24,
      "radiusCost": 2,
      "upkeep": 2,
      "steps": [
        { "action": "wetland", "amount": 0.12 },
        { "action": "meadow", "amount": 0.10 }
      ],
      "care": { "action": "wetland", "amount": 0.04 },
      "harvest": {
        "action": "extract_food", "amount": 4,
        "minMoisture": 0.30, "minFertility": 0.20
      }
    }

顶层 version 为 1，projects 为 1–32 项。key 唯一，name 为 1–24 个字符，steps 为 1–8 项。必须提供 care 与 harvest；对应“维护”和“采集”。amount 范围 0–100，水分和肥力阈值为 0–1。upkeep 为 0–50，baseCost 为 0–200，radiusCost 为 0–20。art 为现有四幅插画的编号 0–3。

解析会拒绝未知动作、重复 key 和超范围数值。客户端加载无效文件时会发出警告并使用内置默认配方；开发者应查看 Godot 日志。配方顺序是 kind 编号，新配置建议在末尾追加项目。

## 动作目录
| action | 含义 |
|---|---|
| meadow | 将适用土地改为草地，增加 amount 肥力 |
| food | 向适用草地或沙地的食物节点注入 amount，受容量约束 |
| rain | 对适用地块施加强度 amount 的局部降雨 |
| wetland | 增加 amount 湿度与约 0.545 × amount 肥力 |
| clear_strip | 按阶段清理横向走廊；管理时清理完整走廊 |
| trail | 按阶段清理斜向通道；管理时保持完整通道 |
| forest_ring | 按阶段恢复相应范围圈中的适用林地 |
| forest | 在适用空地恢复森林；已有森林补充木材并修复植被 |
| mosaic | 按坐标划分森林与粮地，补充对应地表资源 |
| extract_food | 补充适用食物节点，并消耗湿度、肥力与植被 |
| extract_wood | 补充适用木材节点，并消耗湿度、肥力与植被 |

这些动作可以重新组合、调整数值、阶段数、费用与阈值，新增同类工程无需改界面代码。全新的动作语义仍需扩展内核动作处理、存档契约与对应检查；这不是可执行任意代码的脚本系统。
